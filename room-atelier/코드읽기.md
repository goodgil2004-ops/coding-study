# 처음 읽는 룸 아틀리에 코드

## 1. 언어와 화면의 관계

HTML은 버튼·입력란·패널의 구조를 정의합니다. CSS는 색·크기·배치를 정합니다.
JavaScript는 입력을 읽고 상태를 바꾸며, Three.js로 3D 장면을 만듭니다.
Android의 Java 코드는 이 편집기를 WebView에 띄우고 파일 선택·저장을 운영체제에 연결합니다.
웹 서버에서 계산하는 별도 백엔드는 없으며, 제공된 로컬 서버는 파일만 전달합니다.

## 2. 방과 가구를 저장하는 데이터

`app.js`의 `state`가 현재 작업입니다. `state.room`에는 방 크기·색·윤곽이, `state.objects`에는 가구가 들어 있습니다.

| 필드 | 의미 |
|---|---|
| `w`, `d`, `h` | 가로·깊이·높이, cm |
| `x`, `z` | 바닥에서의 가구 중심 위치, cm |
| `y` | 바닥에서 띄우는 높이, cm |
| `rotation` | Y축을 기준으로 도는 각도, 0~359도 |
| `type` | 모델 생성에 사용하는 종류 |
| `color` | 기본 색상 `#rrggbb` |
| `parts` | 직접 만든 가구를 이루는 도형 목록 |
| `assetId` | 가져온 모델 원본 데이터의 식별자 |

Three.js 장면의 길이 단위는 여기서 미터로 다룹니다. 그래서 좌표와 크기를 적용할 때 `/100`을 사용합니다.
`id`는 가구 이름과 다른 고유 식별자이며 `item-숫자` 형식입니다.

## 3. 가구를 추가하면

1. `renderCatalog()`가 기본 목록을 버튼으로 만듭니다.
2. 버튼을 누르면 `addObject()`가 실행됩니다.
3. `checkpoint()`가 실행 취소용 이전 상태를 기록합니다.
4. 새 가구 데이터를 `state.objects`에 넣습니다.
5. `clampObject()`가 방 경계 안으로 위치를 보정합니다.
6. `changed()`가 모델과 패널을 갱신하고 자동 저장을 예약합니다.

`clampObject()`는 방 밖으로 나가는 것을 확인합니다. 가구끼리 겹치는지 검사하는 충돌 시스템은 아닙니다.

## 4. 3D 가구를 그리는 법

`makeFurniture()`는 기본 가구를 상자·원기둥 등의 조합으로 만듭니다.
추가 가구는 `desk-items.js`의 `buildDeskItem()`에서 형태를 만듭니다.
`box(w,h,d,color,x,y,z)`는 상자를 만들고, `cyl()`은 원기둥을 만듭니다.
이 단계의 치수는 상대 비율입니다. 최종 바운딩 박스를 측정해 사용자가 입력한 실제 크기로 맞춥니다.

`custom` 모델은 `models.js`의 `makeParts()`가 도형을 조립합니다.
`imported` 모델은 GLB/glTF/OBJ/STL 로더로 읽은 뒤 크기를 보정합니다.
재질에 일부 고정색이 있으므로 가구의 기본 색상을 바꿔도 모든 부품의 색이 바뀌는 것은 아닙니다.

## 5. 새 가구를 추가하는 수정 위치

예를 들어 새 협탁을 넣으려면 다음 세 가지를 함께 바꿉니다.

1. `desk-items.js`의 `deskItems`에 고유 `type`, 이름, 치수, 색, 카테고리를 추가합니다.
2. 같은 파일의 `buildDeskItem()`에 해당 `type`의 도형 생성 분기를 만듭니다.
3. 실제 화면에서 추가·회전·치수 변경·JSON 저장과 다시 열기를 확인합니다.

`deskKinds`가 목록으로부터 종류 표를 자동 생성하여 저장 파일 검증에 연결됩니다.
새 카테고리까지 만들 경우 `editor.html`의 `data-category` 버튼도 필요합니다.
책상 위 소품은 `desktop:true`를 사용합니다. 최초 위치만 책상 기준으로 설정하며, 책상을 나중에 움직여도 소품이 함께 따라가지는 않습니다.

## 6. 자동 저장 흐름

`autosave.js`의 `createAutosave()`는 상태를 받아 저장 작업을 관리합니다.

- `enable()` 전에는 저장하지 않습니다. 시작할 때 기존 데이터를 읽는 동안 기본 상태가 덮어쓰는 일을 방지합니다.
- `schedule()`은 독립된 JSON 사본을 만듭니다. `_savedAt`을 붙이고 복구 사본을 localStorage에 기록합니다.
- IndexedDB 쓰기는 기본 250ms 대기로 묶어 반복 호출을 줄입니다.
- `drain()`은 쓰기를 직렬로 처리해 오래 걸린 옛 저장이 새 저장을 덮어쓰는 일을 막습니다.
- `flush()`는 저장 버튼·페이지 종료·백그라운드 전환에서 최신 상태를 수집하고 저장을 요청합니다.
- `recoveryCandidates()`는 새 복구 사본, IndexedDB, 구형 저장 데이터를 최신순으로 정렬합니다.
- `app.js`가 후보별 스키마와 모델 데이터를 검사하고 사용 가능한 상태를 복원합니다.

localStorage는 용량이 작아 큰 모델을 포함한 복구 사본은 실패할 수 있습니다. IndexedDB도 브라우저 저장 공간 제한과 사용자의 데이터 삭제 영향을 받습니다. 모든 강제 종료 상황에 대한 무손실 보장은 아닙니다.
제작실에서 아직 방에 추가하지 않은 초안과 실행 취소 이력은 재시작 복원 대상이 아닙니다.

## 7. 파일 내보내기

`projectData()`는 현재 배치와 실제 사용 중인 모델 원본을 모읍니다.
방 JSON에는 모델 원본을 포함할 수 있어 단일 파일로 이동할 수 있습니다.
`file-save.js`는 플랫폼에 맞게 다운로드 또는 iOS 공유 메뉴를 제공합니다.
Android의 `android-bridge.js`는 다운로드 링크를 가로채고, 작은 청크로 Java에 전달해 시스템 저장 대화상자를 엽니다.

## 8. 방 형태와 사용자 제작실

`outline.js`는 사각형·L자형·사용자 윤곽을 점 목록으로 변환하고 면적·점 포함·교차 등을 계산합니다.
`builder.js`는 상자·구·원기둥·원뿔을 조합해 가구를 직접 만드는 제작실입니다.
사진 모델 생성 기능은 삭제했지만, 예전에 사진이 들어간 공간 파일을 불러오는 호환 처리는 남아 있습니다.

## 9. 웹과 Android의 코드 복사본

웹은 `website/dist`, Android는 `android/app/src/main/assets/site`를 사용합니다.
둘을 자동으로 동기화하는 빌드 시스템은 현재 없습니다. 공통 기능을 고칠 때 두 위치에 반영해야 합니다.
Android의 HTML은 `android-bridge.js`와 `android.css`를 추가로 읽습니다. 이것을 지우면 앱 파일 저장이나 터치 배치가 달라질 수 있습니다.

## 10. 안전하게 수정하는 순서

원본 압축을 보관하고 별도 폴더에서 한 기능씩 수정합니다. 먼저 로컬 서버에서 동작을 확인한 뒤 기존 테스트를 실행합니다.
배포 사이트 주소나 서명키를 코드에 넣지 마세요. SDK 빌드와 APK 재패키징의 차이는 루트 README에 설명되어 있습니다.
